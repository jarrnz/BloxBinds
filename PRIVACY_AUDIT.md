# Public release privacy audit

BloxBinds 1.3.0 Beta public developer identity: **wirru**.

Scope: the allowlisted source bundle, release ZIP members, Windows version metadata, unpacked PyInstaller code and data, and inspectable Git identity/history. The final automated scan is required before packaging; results are recorded in TEST_RESULTS.md.

This patch preserves the configured public Git author **wirru** and the existing GitHub noreply email. No email address was invented, Git configuration changed, history rewritten, or commit/tag/push/publication performed for this update. Both existing commits were checked against the public-name/noreply conventions and passed; no identities were printed. Release bundles omit Git metadata. New clones must configure their own public commit identity.

Public bundles omit .git, local settings/calibration, virtual environments, build diagnostics, test caches, previous executables/archives and backups. Local development/build directories can contain machine-specific paths; never publish them. The executable's own version strings use wirru and relative Python code filenames are checked. PE/archive timestamps use a neutral fixed date.

**Optional features:** GitHub update checks are OFF by default and contact only the official public jarrnz/BloxBinds releases API over HTTPS, using a generic User-Agent and no credentials, configurations or personal settings. GitHub receives ordinary connection metadata (including IP address); enabling this is not anonymous networking. The app neither downloads nor executes updates and validates official release-page URLs before opening the browser. Automatic checks occur at most once per session; manual checks require the button. No telemetry was added.

Launch with Windows is OFF by default. Explicit opt-in creates only the BloxBinds value in the current user's standard Run key, containing the local executable command and --startup. Paths remain local; startup registration is excluded from backups and public artifacts. Disable before moving/deleting; a moved app can repair its entry on manual launch, but a deleted executable cannot remove it. Tests use a mocked registry and never register real startup. Portable backups contain validated shortcuts and safe preferences only, excluding paths, monitor coordinates, calibration, credentials, runtime states and machine identifiers. Status-window coordinates stay in local settings. Optional sound uses Windows system aliases without audio assets, services or collection.

**Remaining upstream metadata:** this build's bundled Python/native runtime libraries retain 65 account-directory build/debug references from their upstream compiler environment. They did not match the local developer name, email, Windows account or computer name scanned here. Standard-library documentation also contains generic example account paths. These are explicitly reported rather than claimed absent. Upstream runtime binaries are kept unchanged for reliability; a stricter requirement to remove every vendor build path would require a separately vetted runtime build. No local BloxBinds workspace paths or developer identifiers were found in the inspected executable contents. Upstream Python/Tcl/Tk legal notices identify their respective copyright owners; these are not BloxBinds developer identities.

No publication or Git history rewriting is performed. Review GitHub account visibility, future commit authorship, signing metadata, screenshots, and manually added release files before publication. Static inspection cannot guarantee anonymity or detect every possible secret or indirect identifier.
